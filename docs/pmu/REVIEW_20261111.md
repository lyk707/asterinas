# PMU 评审处理与验证（2026-11-11）

本次在 `41a868e` 上补充测试和使用说明；其 PMU 运行代码与 `edceba5` 相同。
本次未改变生产计数语义、权限策略或调度器，也未修改单独维护的 v3.2 设计报告。

## 评审结论

| 建议 | 核对结果与处理 |
|---|---|
| Intel 缺少通用计数器是 P0 问题 | 固定计数器也是 Intel Architectural PMU 的组成部分。当前 `cycles` / `instructions` 使用固定计数器符合已声明的 v2+ 支持范围；不支持 PMU v1 和通用可编程计数器仍是明确限制。本轮不扩展驱动。 |
| 跨 CPU 迁移覆盖不足 | 正确。补充在两个客体 CPU 上驱动生产调度钩子的内核测试，检查上下文交接。用户态实际任务迁移仍未验证，保留 SKIP。 |
| 不带 `:u` 时需放宽属性校验 | 代码已将该请求映射到 `UserAndKernel`，三个后端均有对应过滤配置。补充不带修饰符的标准 perf 十轮测试，无需改变校验。 |
| 同一线程重复打开同类事件 | 这是现有的显式限制。独立 fd 的 enable、reset、过滤和生命周期需要共享计数模型，不能仅广播增量。本轮保持每类一条的简单模型；`dup` 同一事件 fd 已有测试。 |
| RISC-V 读数改用 CSR | 普通 `Token.read()` 已通过 `Registers::read_counter` 使用 S-mode CSR 读取。跨线程保留硬件配置属于额外优化，当前仍在切出时停止并释放。 |
| Rebase / squash 已发布历史 | 上游送审前可另行整理；本次以独立增量提交更新现有分支，保留已发布提交与历史验证的对应关系。 |

Intel 的硬件分类依据见 [Intel SDM Volume 3B](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-3b-part-2-manual.pdf)。
`--no-inherit` 和显式 `-e cycles,instructions` 仍然必要：不支持继承，也不支持裸 `perf stat` 默认事件集合中的全部事件。

## 新增覆盖

- `kernel/core/src/events/perf/tests.rs`：同一上下文依次在 A、B、A、B、A 上计数；覆盖两类事件的累计、CPU 过滤、切出后的槽位复用，以及不同上下文的计数隔离。
- `run_pmu_tests.sh` / `validate_perf_stat.sh`：分别验证 `cycles:u,instructions:u` 和 `cycles,instructions`，每组十轮，检查正计数、正运行时间和完整调度比例。
- `tools/pmu/runner_tests.py`：覆盖新范围的输出校验，确保零计数或错误地返回 `:u` 事件会导致测试失败。夹具仅验证测试脚本，不属于硬件证据。

内核测试在真实客体 CPU 上调用 `PerfContext::on_schedule_in/out`，经过实际 PMU 后端。
它验证 PMU 上下文的跨 CPU 交接，不包含调度器搬迁同一任务、用户态 ABI 与迁移并发的端到端证明。
当前 `sched_setaffinity` 的源码仍明确说明尚不支持迁移，唤醒路径也直接选择 `last_cpu`；增加 `yield` 或工作线程不能替代这一能力。
